Mainnet replay checks

Would this change alter the outcome of a transaction already on gno.land mainnet? For every push to a tracked branch and every PR into one, gnoreplay builds the commit's node and replays the entire history of gnoland-1 with it, every block from genesis to a recent height, comparing each transaction's result (error, returned data, events) and gas with what the chain recorded.

How it works, and how to read a result
  • pass no transaction's result changes. Gas-only differences are listed, but pass: on their own, they change no outcome.
  • diverges at least one transaction's result, or a block, differs from mainnet where the base branch's latest replay matches it. Divergences the base branch has too are counted as inherited, not new. After the first app hash mismatch, diffs may be consequences of earlier ones: read from the top.
  • error the replay could not run (build or worker failure, timeout): nothing was checked.
  • superseded a newer push came first, or the PR was closed.
  • skipped the PR only changes files that can't affect the node (documentation, tests, CI, examples or tools). Pushes to branches are always replayed.

A PR is replayed merged into its base branch (GitHub's test merge, what CI tests), so what its branch lacks from the base doesn't show as divergences. When it conflicts, its head is replayed as is, and its page says so.

A divergence is not necessarily a bug: intended behavior changes are expected to be gated by height, or shipped through a coordinated upgrade.

GitHub is polled every {{.PollInterval}}. Each new head is queued in the priority order below, superseding its PR's or branch's previous replay, and replayed on a disposable machine of its own: up to {{.Workers}} at once, about 1h45m each (at most {{.RunTimeoutMinutes}} minutes). PRs that were already open when the server started are replayed from their next push. The server only reads from GitHub: it posts no statuses or comments, results are published here only.
